# n8n Course Kit

Невеликий навчальний пакет для Windows: повідомлення Telegram проходить через
публічний HTTPS tunnel у локальний n8n, а workflow надсилає відповідь назад.

Поточний навчальний сценарій:

`Привіт` → `Отримано: Привіт`

AI-модель у першу версію не входить. Спочатку пакет перевіряє надійну й
захищену доставку подій.

## Що потрібно

- Windows 11;
- Docker Desktop із запущеним Linux Engine;
- інтернет;
- власний Telegram-бот, створений через офіційного [@BotFather](https://t.me/BotFather).

На HP Pavilion 14-ce0064ur уже підтверджено запуск Docker Linux-контейнера.
Повна перевірка пакета на цьому ноутбуці виконується після складання.

## Перший запуск

1. Відкрийте Docker Desktop і дочекайтеся стану **Engine running**.
2. У Telegram відкрийте `@BotFather`, виконайте `/newbot` і збережіть виданий токен.
3. Надішліть новому боту будь-яке приватне повідомлення, наприклад `/start`.
4. Двічі натисніть [start.cmd](start.cmd).
5. Вставте токен у масковане поле. Токен не надсилайте в чат і не додавайте у Git.
6. Натисніть **Знайти ID після повідомлення боту** або введіть свій числовий user ID.
7. Натисніть **Зберегти налаштування**, потім **Запустити**.
8. Під час першого запуску браузер відкриє n8n. Створіть локальний обліковий
   запис власника, поверніться у вікно й ще раз натисніть **Запустити**.
9. Дочекайтеся зеленого стану **готово** й напишіть боту текстове повідомлення.

Пошук ID використовує офіційний Telegram Bot API. Якщо в бота вже налаштований
інший webhook, пакет не змінює його автоматично. Для курсу краще створити окремого бота.

## Щоденна робота

- **Запустити** — перевіряє Docker і Telegram, запускає n8n, proxy та tunnel,
  готує workflow й реєструє webhook.
- **Відкрити n8n** — відкриває локальний редактор на `127.0.0.1`.
- **Перевірити** — перевіряє готовність бази n8n і адресу Telegram webhook.
- **Зупинити** — видаляє лише webhook цього пакета та зупиняє його контейнери.
  Дані n8n і налаштування залишаються.

Навчальний workflow створюється один раз. Наступні запуски оновлюють credential
бота, але не перезаписують зміни студента у workflow.

Публічна адреса Quick Tunnel змінюється після нового запуску. Launcher отримує
нову адресу та реєструє її в Telegram. Поки ноутбук вимкнений або спить, бот не працює.

## Де зберігаються дані

- база й workflow n8n: Docker volume `n8n-course-kit_n8n_data`;
- JavaScript Code node виконується в офіційному зовнішньому task-runner sidecar,
  окремо від процесу n8n;
- локальні налаштування: `%LOCALAPPDATA%\N8nCourseKit`;
- токен, ключ n8n і webhook secret: у DPAPI-зашифрованому файлі поточного
  користувача Windows;
- тимчасові відкриті значення: у закритій ACL runtime-папці тільки під час роботи.

Секрети не зберігаються в репозиторії. Після штатної зупинки runtime-папка видаляється.
Адміністратор Windows або шкідлива програма з правами цього користувача все одно
можуть читати дані під час роботи — DPAPI не замінює захищену операційну систему.

## Резервна копія і відновлення

- Двічі натисніть [backup.cmd](backup.cmd), щоб створити ZIP у
  `Документи\N8nCourseKitBackups`.
- Двічі натисніть [restore.cmd](restore.cmd), оберіть ZIP і підтвердьте заміну.
  Перед нею скрипт створить страхову копію поточного стану.

Під час backup n8n коротко зупиняється для узгодженої копії SQLite, а tunnel
залишається запущеним. Архів містить базу й персональні дані. DPAPI-секрети з
нього відновлюються лише тим самим користувачем Windows на цьому ПК. Після
restore запустіть пакет звичайною кнопкою **Запустити**.

## Типові проблеми

**Docker Engine не відповідає.** Відкрийте Docker Desktop і дочекайтеся
`Engine running`, потім повторіть запуск.

**Порт 5678 зайнятий.** Закрийте програму, яка його використовує. Зміна порту
підтримується ядром пакета, але в першому GUI ще не винесена в окреме поле.

**Бот уже має інший webhook.** Використайте окремого навчального бота або
свідомо приберіть стару інтеграцію. Пакет не перезаписує її автоматично.

**Tunnel не отримав адресу.** Перевірте інтернет, корпоративний firewall або VPN.
cloudflared потребує вихідного з'єднання; відкривати порт на роутері не треба.

**Telegram показує помилку доставки.** Натисніть **Перевірити**. Після сну
ноутбука зупиніть і знову запустіть пакет, щоб отримати новий tunnel.

## Тести для розробника

У PowerShell із кореня пакета:

```powershell
python tests/run_tests.py
```

З реальною перевіркою nginx у тимчасовій Docker-мережі:

```powershell
.\tests\run-tests.ps1 -DockerIntegration
```

Повний тест офіційного CLI n8n, імпорту, публікації та production webhook:

```powershell
.\tests\run-tests.ps1 -DockerIntegration -ComposeIntegration -FullN8nIntegration -PublicTunnelIntegration
```

Перший повний запуск тестів може тривати кілька хвилин.

Тести створюють лише ресурси з префіксом `coursekit-...-test` і прибирають їх.
План сценаріїв: [TEST_PLAN.md](TEST_PLAN.md). Опис мережі й перенесення на VPS:
[INFRASTRUCTURE.md](INFRASTRUCTURE.md). Обґрунтування вибору tunnel і версій:
[RESEARCH.md](RESEARCH.md). Команди для Codex Cloud: [CLOUD_ENVIRONMENT.md](CLOUD_ENVIRONMENT.md).

## Межі перевірки

У хмарній Linux-сесії перевіряються Compose, workflow, nginx і CLI n8n.
WinForms, Windows DPAPI, шляхи з кирилицею та реальний Telegram E2E потрібно
остаточно перевірити на цільовому Windows-ПК. Непройдені перевірки не вважаються успішними.
