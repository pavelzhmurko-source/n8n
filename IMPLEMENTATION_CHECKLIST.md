# Чек-лист реалізації навчального пакета

Версія 0.1 · 8 листопада 2026 року.

Це робочий порядок для розробника: за ним створюється та перевіряється пакет.
Створення цього документа не означає початок реалізації або погодження
користувачем усіх проєктних рішень.

Основа: [ТЗ](SPEC.md), [інфраструктура](INFRASTRUCTURE.md),
[roadmap](ROADMAP.md), [план тестування](TEST_PLAN.md),
[архітектурні рішення](ARCHITECTURE.md).

## Як користуватися чек-листом

- `[x]` ставити лише після отримання доказу виконання, а не після написання коду.
- Порядок: опис поведінки → тест → реалізація → перевірка → запис результату.
- Тести T01–T17 означають сценарії з TEST_PLAN.md, а не вже готові тестові файли.
- Для перевірок записувати команду або ручні дії, версії, середовище та результат:
  PASS / FAIL / BLOCKED / NOT RUN. Секрети до доказів не включати.
- Зберігати поточні зміни користувача; працювати в наявному checkout.
- Блокування Windows-перевірки не заважає незалежній роботі, але не дозволяє
  позначити відповідний пункт виконаним або оголосити пакет готовим.
